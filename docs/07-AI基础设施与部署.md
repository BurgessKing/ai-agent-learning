## 一、AI 基础设施（底座）

### 1.1 GPU 与显存 — 选型决策

```
模型部署显存估算:

  显存 ≈ 参数量 × 精度字节数 × 1.2（推理开销）

  FP32 (4B/param):  7B 模型 ≈ 7×4×1.2 = 33.6 GB
  FP16 (2B/param):  7B 模型 ≈ 7×2×1.2 = 16.8 GB
  INT8 (1B/param):  7B 模型 ≈ 7×1×1.2 = 8.4 GB
  INT4 (0.5B/param):7B 模型 ≈ 7×0.5×1.2 = 4.2 GB

常见 GPU 显存:
┌──────────────┬──────────┬─────────────────────────┐
│ GPU          │ 显存     │ 能跑什么                  │
├──────────────┼──────────┼─────────────────────────┤
│ RTX 3080     │ 10/12GB  │ QLoRA 微调 7B，推理 13B  │
│ RTX 4090     │ 24GB     │ 推理 34B，QLoRA 13B      │
│ A100         │ 40/80GB  │ 全量微调 13B，推理 70B   │
│ H100         │ 80GB     │ 全量微调 70B             │
└──────────────┴──────────┴─────────────────────────┘

对于公交项目推荐:
  - 开发/调试: DeepSeek API（按量付费，月成本¥30）
  - 本地推理: RTX 3080 + Ollama + Qwen2.5-7B-Q4（免费）
  - 本地微调: RTX 4090 + QLoRA（消费级可做）
```

## 二、模型训练与微调

### 2.1 训练全链路

```
Pre-training（预训练）
  数据: 万亿级 Token 互联网语料
  成本: 7B 模型约 $50万-$100万
  产出: Base Model（会接话，不会听话）
        ↓
SFT（监督微调）
  数据: 万级高质量指令-回答对
  成本: 7B 模型约 $100-500
  产出: Chat Model（会听话了）
        ↓
RLHF / DPO（对齐）
  数据: 千级人类偏好对比
  成本: 7B 模型约 $50-200
  产出: Aligned Model（安全、有用）
```

**面试话术**：
> "我们不做预训练。SFT 能改变模型的回答风格，DPO 能减少有害输出。实际项目中，如果 API 模型的输出风格不满足需求，我们会收集 500-1000 条高质量对话做 SFT。"

### 2.2 LoRA — 高效微调

```python
"""
LoRA 原理: 冻结原模型，插入低秩矩阵
  原参数 W (d×d): 不动
  LoRA: A(d×r) × B(r×d)，r << d
  最终: W' = W + A×B

  参数量对比（7B 模型）:
    全量微调: 7B 参数 = 28GB (单卡不够)
    LoRA(r=16): 约 33M 参数 = 132MB（单卡 RTX 3080 即可）
    QLoRA: 4bit 基础模型 + LoRA = 约 10GB 显存
"""

from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B")

lora_config = LoraConfig(
    r=16,                    # 秩（越大越强，越大越慢）
    lora_alpha=32,           # 缩放因子（通常 2×r）
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],  # 要插入的层
    lora_dropout=0.1,
    bias="none",
    task_type="CAUSAL_LM",
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# trainable params: 33,554,432 || all params: 7,073,108,480 || trainable%: 0.47%
```

**关键参数**：

| 参数 | 含义 | 建议值 |
|------|------|--------|
| r | LoRA 秩 | 8-64，越大效果越好但越慢 |
| lora_alpha | 缩放因子 | 通常 2×r |
| target_modules | 插入哪些层 | QKV 全部比只插 Q 效果好 |
| dropout | 防止过拟合 | 0.05-0.1 |
| learning_rate | 学习率 | 1e-4 ~ 5e-4 |

## 三、模型量化

### 3.1 量化方法对比

```
量化本质: 把 32-bit 权重压缩到 8-bit / 4-bit

┌──────────┬─────────┬──────────┬─────────────────┐
│ 方法      │ 精度     │ 显存节省  │ 适用场景         │
├──────────┼──────────┼──────────┼─────────────────┤
│ GPTQ     │ INT4/8  │ 75%      │ GPU 推理         │
│ AWQ      │ INT4    │ 75%      │ GPU 推理(更快)   │
│ GGUF     │ Q2-Q8   │ 50-85%   │ CPU/混合推理     │
│ bitsandbytes│ INT4/8│ 75%      │ QLoRA 微调       │
└──────────┴─────────┴──────────┴─────────────────┘

选型建议:
  - GPU 服务器推理 → AWQ（速度最快）
  - 本地 Mac/CPU → GGUF（llama.cpp 生态）
  - QLoRA 微调 → bitsandbytes NF4
```

### 3.2 显存计算器

```python
def vram_calculator(model_size_b: int, precision: str, overhead: float = 1.2):
    """模型显存估算"""
    bytes_per_param = {
        "FP32": 4, "FP16": 2, "INT8": 1, "INT4": 0.5,
        "NF4": 0.55, "GGUF_Q4": 0.55,
    }
    bpp = bytes_per_param.get(precision, 2)
    vram = model_size_b * bpp * overhead / (1024**3)
    return round(vram, 1)

# 示例
print(f"Qwen2.5-7B FP16:  {vram_calculator(7e9, 'FP16')} GB")   # 16.8 GB
print(f"Qwen2.5-7B INT4:  {vram_calculator(7e9, 'INT4')} GB")   # 4.2 GB
print(f"Qwen2.5-72B INT4: {vram_calculator(72e9, 'INT4')} GB")  # 43.2 GB

# 实际场景: RTX 3080 (10GB)
# 能跑: Qwen2.5-7B-Q4 + KV Cache (约 8GB 总)
# 不能跑: Qwen2.5-13B-FP16 (需要约 31GB)
```
